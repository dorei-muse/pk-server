# pk-server
Server for signing `.pkpass`es generated by PassKeepr

## Usage
```
curl -F "pkpass=@path/to/pass.pkpass" https://[url]/sign --output path/to/output.pkpass
```

# Rate limiting

`POST /sign` is rate limited per client IP, using `express-rate-limit`:

* Burst: 5 requests per minute
* Sustained: 20 requests per hour

A request over either limit gets `429` with `{"error":"Too many signing requests, try again later"}`, plus standard `RateLimit-*` and `Retry-After` headers. The limiters run before the file upload is accepted, so rejected requests do not cost the server a 20MB upload and a signing attempt.

Tune the limits without a code change with `RATE_LIMIT_BURST_MAX` / `RATE_LIMIT_BURST_WINDOW_MS` and `RATE_LIMIT_HOURLY_MAX` / `RATE_LIMIT_HOURLY_WINDOW_MS` (defaults: 5 / 60000 and 20 / 3600000).

Two limits to know about:

1. This is not authentication. An attacker can still get passes signed, just slower (20/hour per IP). The real fix for that is a shared secret only PassKeepr sends, plus an allowlist of `passTypeIdentifier` values.
2. This is not a hard cap on Vercel. Counters live in memory per function instance, and Vercel runs many instances with cold starts that reset them, so a distributed attacker can exceed 20/hour in total. A hard cap needs a shared store (Upstash Redis / Vercel KV) or Vercel Firewall rate limiting in front of the app.

# Environment Variables

A few environment variables are needed to sign passes. They are as follows:

* `PK_key` is the **unencrypted** private key from the CSR that is generated locally using Keychain Access (following these instructions: https://developer.apple.com/help/account/certificates/create-a-certificate-signing-request). Note that when you generate the CSR according to these instructions it creates a new key pair in your keychain with the Common Name you entered (so picking a name that already exists in your keychain is allowed but is annoying to deal with) You can export this as a `.p12` using Keychain Access (you can skip the export password by just not entering one), and then convert it to a `.pem` using the following:

```
openssl pkcs12 -in private-key.p12 -nocerts -out pass-key.pem -nodes
```

* `PK_cert` and the suffixed `PK_cert_[1-10]` are the converted "Pass Type ID" cert that are created using the CSR, and can be downloaded from the Apple Developer website (https://developer.apple.com/account/resources/certificates/list). It is nice to have the bag attributes added to this cert, which can be done with the following:

```
openssl x509 -in pass.cer -inform der -out pass-cert.pem # convert the .cer downloaded from the Apple Developer website to .pem
openssl pkcs12 -export -inkey pass-key.pem -in pass-cert.pem -out pass.p12 # Combine cert and private key into a .p12
openssl pkcs12 -in pass.p12 -nokeys -out pass-cert-with-bag.pem # Convert from .p12 into .pem with Bag Attributes
```

Where `pass-key.pem` comes from the private key generated with your CSR as described above

* `WWDR_cert` is the WWDR intermediary cert, available from http://www.apple.com/certificateauthority/

You can verify the validity of your environment by signing a pass and using the `signpass` tool with the `-v` flag or by trying to open the signed pass in macOS (double click in Finder). Properly signed passes will open in a small preview window.
